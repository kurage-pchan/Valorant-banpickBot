# Valorant バンピックBot 仕様

## 1. 目的

Discord上でVALORANTのマップバンピックを進行するBotを作る。

## 2. 決定事項

| 項目 | 仕様 |
| --- | --- |
| 利用場所 | Discord |
| 対象 | マップのバンピック |
| 対応する試合形式 | BO1、BO3、BO5 |
| 開始方法 | `!bp1`、`!bp3` などのコマンド |
| キャンセル | `!bpcancel` |
| ダイス機能 | `!dice` で通常のダイスを振れる |
| 選択入力 | Botが促した後に、マップ番号または攻守番号を数字で入力する |
| 進行方法 | Botが次の操作をチャットで促す |
| ユーザー識別 | チャットを送信したDiscordユーザーを識別する |
| マッププール | コード内の一か所に定義し、管理者がそこを編集して変更する |
| マップ一覧確認 | `!maplist` |
| 実行場所 | ローカルPCでPythonプログラムを起動する |
| 実装方針 | 既存のDice Botと同じ `discord.py` のBotを拡張する |
| マッププールの保存 | ソースコードに保存し、Bot再起動後も同じ設定を利用する |
| 試合結果の保存 | 保存しない。終了時の表示のみ行う |
| 同時進行 | 1チャンネルにつき1試合 |
| AI機能 | 実装しない |
| 初期スコープ | バンピックを最後まで進行できる最小機能 |

## 3. 初期版で必要な機能

- `!bp1`、`!bp3`、`!bp5` でバンピックを開始する
- `!dice` で1〜100のダイスを振り、結果を表示する
- `!maplist` で現在のマッププールを表示する
- 開始した試合の形式を管理する
- 現在の手番を管理する
- Botが次に操作するチームまたはユーザーを案内する
- Discordユーザーと選択内容を記録する
- 選択されたマップをバンまたはピック済みとして管理する
- `!maplist` でコードに定義されたバンピック対象のマップ一覧を確認できる
- ルールに従ってバンピックを進行する
- 終了時に最終的なマップ結果を表示する
- 進行中のチャンネルで新しい開始コマンドを受けた場合は拒否する
- `!bpcancel` で進行中の試合をキャンセルする

## 4. 共通仕様

### 4.1 試合開始と代表者登録

1. `!bp1`、`!bp3`、`!bp5` のいずれかを入力したユーザーをチームAの代表者として登録する。
2. ダイスは `!dice` で事前に実行し、ダイスの勝者がチームA/Bのどちらを担当するか話し合いで決める。
3. チームAの代表者が `!bp1`、`!bp3`、`!bp5` を入力してバンピックを開始する。
4. Botは開始者をチームA代表者として扱い、最初の手順をチームAに促す。
5. チームBの最初の手番で有効な番号を入力したユーザーをチームB代表者として登録する。
6. 以降、チームA/Bの代表者が自分のチームの手番を操作する。

ダイスが同点の場合は、参加者が `!dice` を再実行して振り直す。

### 4.2 マッププールと番号入力

初期マッププールは以下の7マップとする。実装時はコード内の `MAP_POOL` を編集して変更できる。

1. ASCENT
2. SPLIT
3. LOTUS
4. FRACTURE
5. HAVEN
6. ICEBOX
7. PEARL

- マップ一覧は `MAP_POOL` に定義し、Bot起動中および再起動後もその設定を利用する。
- `MAP_POOL` のマップ数は7個に固定する。7個未満または7個を超える場合、バンピックの開始を拒否する。
- Botは各手順で、その時点で選択可能なマップを番号付きで表示する。
- ユーザーは表示された番号を入力する。
- 表示された選択肢にない番号や、すでに選択済みの番号は受け付けない。
- チームB代表者が未登録の場合、最初の有効な番号を入力したユーザーをチームB代表者として登録する。
- チームB代表者の登録に使用した番号を、そのまま最初のBANまたは選択として処理する。

### 4.3 操作権限

チームA、チームBそれぞれの代表者が、自分のチームの手番を実行できる。
現在操作するチームの代表者以外がコマンドを送信した場合は拒否し、バンピックの状態を変更しない。
開始コマンドの実行者が操作担当者でない場合も、同様に拒否する。
無効な入力の場合は、入力を受け付けず、正しい番号の入力を促すメッセージを表示する。

### 4.4 攻守選択

Botは以下の番号で攻撃側または防衛側を表示し、対象チームの代表者だけが番号を入力する。

1. ATTACKER
2. DEFENDER

### 4.5 試合状態

- `!bp1`、`!bp3`、`!bp5` の受付から、終了メッセージの表示までを「進行中の試合」とする。
- 進行中の試合があるチャンネルでは、新しい開始コマンドを拒否する。
- 別のチャンネルでは、別のバンピックを進行できる。
- 試合状態は保存しないため、Botを再起動すると進行中の状態も破棄される。
- チームAまたはチームBの代表者は、`!bpcancel` で進行中の試合をキャンセルできる。
- キャンセル時は結果を表示・保存せず、同じチャンネルで新しい試合を開始できる。

## 5. BO1ルール

### 5.1 マップBAN

1. チームA、チームBの順に交互にBANを行う。
2. 選択されたマップをBANし、残りのマップ一覧を更新する。
3. 最後に残ったマップをBO1の試合マップとする。

### 5.2 攻守選択

1. 最後に残ったマップを表示する。
2. チームAの代表者に攻撃側または防衛側の選択を促す。
3. チームA代表者が攻撃側または防衛側を入力する。
4. チームBにはチームAと反対の陣営を割り当てる。

### 5.3 終了メッセージ

バンピック終了時に、以下の情報をDiscordへ表示する。

- `BAN&PICKを終了します。`
- 最終マップ
- チームA代表者と選択した陣営
- チームB代表者と選択した陣営

## 6. BO3ルール

BO3では、以下の順番でマップBAN、マップ選択、攻守選択を行う。

1. チームAがBANするマップの番号を入力する。
2. チームBが残りのマップからBANするマップの番号を入力する。
3. チームAが残りのマップからマップ1として使用するマップの番号を入力する。
4. チームBがマップ1の攻撃側または防衛側を番号で選択する。
5. チームBが残りのマップからマップ2として使用するマップの番号を入力する。
6. チームAがマップ2の攻撃側または防衛側を番号で選択する。
7. チームAが残りのマップからBANするマップの番号を入力する。
8. チームBが残りのマップからBANするマップの番号を入力する。
9. 最後に残ったマップをマップ3とし、チームAが攻撃側または防衛側を番号で選択する。

各手順では、Botがその時点で選択可能なマップを番号付きで表示し、対象チームの代表者だけが入力できる。
攻撃側・防衛側の番号と、チームA/B代表者の登録方法は共通仕様に従う。

## 7. BO5ルール

BO5では、以下の順番でマップBAN、マップ選択、攻守選択を行う。

1. チームAがBANするマップの番号を入力する。
2. チームBが残りのマップからBANするマップの番号を入力する。
3. チームAが残りのマップからマップ1として使用するマップの番号を入力する。
4. チームBがマップ1の攻撃側または防衛側を番号で選択する。
5. チームBが残りのマップからマップ2として使用するマップの番号を入力する。
6. チームAがマップ2の攻撃側または防衛側を番号で選択する。
7. チームAが残りのマップからマップ3として使用するマップの番号を入力する。
8. チームBがマップ3の攻撃側または防衛側を番号で選択する。
9. チームBが残りのマップからマップ4として使用するマップの番号を入力する。
10. チームAがマップ4の攻撃側または防衛側を番号で選択する。
11. 最後に残ったマップをマップ5とし、チームBが攻撃側または防衛側を番号で選択する。

各手順では、Botがその時点で選択可能なマップを番号付きで表示し、対象チームの代表者だけが入力できる。

## 8. 実行・実装方針

- BotはローカルPC上でPythonから起動する
- 初期版はWeb画面、外部サーバー、データベースを使用しない
- 既存のDice Botと同じ `discord.py` の `Client` とメッセージイベントを利用する
- マップ一覧は `MAP_POOL` などの定数としてコード内の一か所に定義する
- マップ一覧を変更する場合は、その定数を編集してBotを再起動する
- DiscordのBotトークンや管理者IDはソースコードへ直接記述せず、環境変数などで設定する
- 操作ユーザー以外のコマンドは実行せず、エラーメッセージを返す
